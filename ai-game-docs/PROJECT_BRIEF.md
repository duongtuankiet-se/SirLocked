# SirLocked AI Cooperative Detective Game

## Goal

Build a runnable MVP for SirLocked: a web-based cooperative detective game platform for 2 players. The platform uses structured case JSON, optionally generated by AI, to render a playable point-and-click / visual novel investigation game from start to finish.

The MVP must prioritize a playable demo over advanced architecture.

## Problem Statement

Most small detective-game prototypes become static story pages or CRUD case managers. SirLocked solves a narrower problem: make a structured mystery case playable as a real-time, two-player investigation where the backend enforces clue discovery, dialogue locks, scene progress, and final accusation logic.

The product should prove that a case JSON file can drive a complete game loop without hard-coded scene logic in the frontend.

## Target Users

- `PLAYER`: two friends/classmates who want a short cooperative detective session in a browser.
- `ADMIN`: a project owner or teacher/evaluator who needs to seed, import, validate, publish, and demo playable cases.
- Future `CASE_CREATOR`: a user who prompts AI to generate case drafts for admin review. This is not required for MVP unless it can be added without weakening the core playable loop.

## Core Value

- Players get a complete co-op mystery flow: join room, split roles, discover clues, interrogate characters, and solve or fail the case.
- Admins get a predictable data-driven case format that can be validated before publish.
- The team gets an AI-friendly spec: entities, routes, state, validation rules, realtime events, and acceptance tests are explicit enough for a coding agent to implement consistently.

## MVP Scope

In scope:

- JWT auth for `PLAYER` and `ADMIN`.
- Published case list/detail.
- Admin seed/import/validate/publish case.
- Two-player room with non-duplicate roles.
- Realtime lobby and gameplay sync.
- Scene renderer driven by case JSON.
- Hotspot item inspection.
- Dialogue with clue requirements.
- Clue board and current objective/hint panel.
- Scene/stage progression.
- Final accusation using clue evidence IDs.
- Result win/fail ending.
- Single-step AI case draft generation with mock fallback.

Out of scope for MVP:

- Real generated images and Cloudinary upload.
- Multi-step AI generation pipeline.
- AI validator using a second model.
- Full admin analytics dashboard.
- Room chat/action log as a required feature.
- Payments, subscriptions, leaderboards, ratings, replay system.
- More than two active players.

## Product Type

SirLocked is not a simple CRUD app. It is a game platform with:

- published detective cases
- realtime 2-player rooms
- role selection
- scene-based gameplay
- clickable hotspots
- item inspection
- character dialogue
- clue unlocking
- stage progression
- final deduction
- win/fail ending
- admin case management
- AI case generation

## Core Gameplay

1. Player logs in.
2. Player chooses a published case.
3. Player creates a room or joins by room code.
4. Two players choose non-duplicate roles.
5. Host starts the game.
6. Game loads the first stage and scene.
7. Players inspect items and talk to characters.
8. Backend unlocks clues and dialogue based on case logic.
9. Players complete scenes and stages.
10. Players submit final accusation.
11. Backend validates culprit and evidence.
12. Game shows win or fail ending.

## User Roles

- `PLAYER`: can register, login, view published cases, join rooms, play games.
- `ADMIN`: can manage users/cases, seed sample cases, import case JSON, publish/unpublish cases, generate AI case drafts.

Optional future role:

- `VIP`: can generate AI cases for admin review. Do not add this for MVP unless it is easy and does not break existing code.

## Current Repository Stack

- Backend: ASP.NET Core Web API, C#, MongoDB, JWT, SignalR.
- Frontend: React + Vite using JavaScript/JSX.
- Database: MongoDB.
- Realtime: SignalR.
- AI case generation: Deepseek for JSON.
- Image generation and Cloudinary: optional for MVP; use placeholders when keys are missing.

Do not migrate the frontend to TypeScript for MVP.

## MVP Principle

Implement the shortest reliable path to a complete playable demo:

- sample case
- published case list
- room/lobby
- realtime start
- playable scene
- hotspots
- clue unlock
- dialogue unlock
- final accusation
- result
- admin seed/import/publish
- AI JSON generation with fallback

## Future Expansion Direction

Keep MVP code simple, but avoid choices that block these later features:

- VIP role for user-generated AI cases pending admin review.
- Multi-step AI pipeline: overview, content, asset prompts, validation, image generation, compile, preview, publish.
- AI validator that checks story logic, clue reachability, contradiction chains, and deadlocks.
- Real generated image assets uploaded to Cloudinary.
- More than 2 players or spectator mode.
- Player history, ratings, leaderboards, and replayable case result summaries.
- Case editor for admins to repair AI-generated JSON before publishing.
- Localization for UI labels and potentially case content.
